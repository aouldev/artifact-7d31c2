Protocol

Two-stage evaluation, one public leaderboard

The leaderboard separates intent recognition from patch analysis, matching the benchmark pipeline used by the private server evaluator.

01

Intent Classification

Every validation episode is scored as positive or negative. The table ranks by Intent Macro-F1 by default to reduce class-imbalance bias.

  • Accuracy
  • Macro-F1
  • Positive precision / recall / F1
02

Static Patch Analysis

Patch metrics are computed only when gold=positive and prediction=positive. This stage checks patch presence, git-apply success, and target test-file overlap against hidden gold metadata.

  • Patch apply rate
  • Patch presence rate
  • True-positive target coverage
03

Dynamic Validation

Server-side repo-specific runners reuse prepared snapshots and dependency caches, then run build/compile checks and changed tests after applying each participant patch.

  • CSR: compile/build success rate
  • TPS: targeted changed-test pass rate
  • End-to-end dynamic success
